# popo_team_board_update

编辑（修改）群组公告内容，支持修改、覆盖或清空。可选择是否将公告变更发送到群聊。

> ⚠️ **注意**：该操作会**整体覆盖**原有群公告，不是追加内容。如需在原公告基础上修改，先用 `popo_team_info_query(type=1)` 读取原文，再拼接后提交完整公告。

> 🧹 **清空群公告**：`board` 传空字符串且 `type=3`。清空同样属于破坏性操作，执行前必须与用户确认。

## 命令

```bash
# 修改群公告，不发送到群聊（type 省略时默认 1）
popo-cli popo team_board_update tid=1000114924 board="新的群公告内容"

# 修改群公告，并发送到群聊通知群成员
popo-cli popo team_board_update tid=1000114924 type=2 board="新的群公告内容"

# 清空群公告（board 为空，type 必须为 3）
popo-cli popo team_board_update tid=1000114924 type=3 board=""
```

## 请求参数

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `type` | Integer | 否 | `1` | 公告变更类型：`1` 不发送到群聊（默认），`2` 发送到群聊，`3` 清空群公告（需 `board` 为空） |
| `tid` | String | **是** | - | 群 ID（通过 `popo_team_search` 获取的 `content.tid`，与 `team_info_query` 等群操作参数名一致） |
| `board` | String | 否 | - | 群公告内容；清空群公告时传空字符串 `""`（配合 `type=3`） |

## 响应参数

无返回数据。操作成功时 `popo-cli` 命令正常返回，失败时返回错误信息。

## 使用要点

### 修改流程

1. **解析群 ID**：用户提到群名时，先通过 `popo_team_search` 获取 `content.tid`（即 `tid` 参数）
2. **确认公告内容**：与用户确认新的公告内容 `board`；若用户要求"清空公告 / 删除公告"，则 `board` 传空字符串
3. **判定 `type`**（规则见下方取值判定表）：
   - 清空群公告（`board` 为空）→ `3`
   - 用户明确要求发送到群聊 → `2`
   - 其他情况（含用户未说明）→ `1`（默认，不发送到群聊），**无需追问**
4. **调用修改**：调用 `popo_team_board_update`，传入 `tid`、`board`、`type`
5. **结果反馈**：告知用户群公告已修改（或已清空），并说明是否已发送到群聊

### type 取值判定

| 场景 / 用户表达 | type |
|---------|------|
| 清空群公告（此时 `board=""`） | `3` |
| "改公告并发送到群聊""在群里通知一下""同步到群里" | `2` |
| "只改公告""不要发到群里""不用通知群成员" | `1` |
| 未明确说明是否发送到群聊 | `1`（默认，**无需追问**） |

### board 传参注意事项

- 公告内容通常较长且可能包含换行，必须使用**双引号**包裹：`board="新的群公告内容"`
- **macOS / Linux**：双引号直接传递即可
- **Windows**：公告内容含换行或特殊字符时，必须写入 UTF-8 无 BOM 临时文件后通过 `board="@text:$tmpFile"` 传递（与发送消息 `message` 参数同一套 `try/finally` 清理流程，详见 SKILL.md「Windows 铁律 — 所有 `message` 参数必须走 `@text:` 临时文件」）。禁止手工拼接字符串，禁止使用 `Set-Content` / `Out-File`
- 公告内容中的双引号需按 shell 规则转义（macOS / Linux 用 `\"`），Windows 走临时文件可完全避免转义问题

### 注意事项

- 需要有编辑群公告的权限（通常仅群主 / 群管理员）
- 编辑（含清空）群公告属于破坏性群操作，执行前**必须与用户确认**新的公告内容（清空时确认清空意图）后再执行
- `board` 会覆盖原有公告，不是追加；需要保留原内容时先通过 `popo_team_info_query(type=1)` 读取
- 清空群公告必须同时满足 `board` 为空字符串且 `type=3`；不要用空 `board` 搭配 `type=1` / `type=2` 表达清空意图
- 如果 `popo-cli` 返回错误，将错误信息报告给用户，不要自行重试

### 典型场景

#### 场景一：直接修改并通知群成员

```
用户：「把项目讨论群的群公告改成『本周五下午 3 点开全员会议』，顺便在群里通知一下」
  ├─ Step 1: popo_team_search("项目讨论群") → tid=1000114924
  ├─ Step 2: 与用户确认新公告内容，type=2（发送到群聊）
  └─ Step 3: popo_team_board_update(tid=1000114924, board="本周五下午 3 点开全员会议", type=2)
```

#### 场景二：在原公告基础上追加，不通知群成员

```
用户：「看一下项目讨论群的公告，在末尾加上『请及时更新周报』，不要发到群里」
  ├─ Step 1: popo_team_search("项目讨论群") → tid=1000114924
  ├─ Step 2: popo_team_info_query(tid=1000114924, type=1) → 读取原公告 board 原文
  ├─ Step 3: 拼接原公告 + "请及时更新周报"（整体覆盖）
  └─ Step 4: popo_team_board_update(tid=1000114924, board="<拼接后的完整公告>", type=1)
```

#### 场景三：清空群公告

```
用户：「把项目讨论群的群公告清空」
  ├─ Step 1: popo_team_search("项目讨论群") → tid=1000114924
  ├─ Step 2: 与用户确认清空操作
  └─ Step 3: popo_team_board_update(tid=1000114924, board="", type=3)
```

#### 场景四：用户未说明是否发送到群聊（默认不发送，无需追问）

```
用户：「把项目讨论群的群公告改成『本周五下午 3 点开全员会议』」
  ├─ Step 1: popo_team_search("项目讨论群") → tid=1000114924
  ├─ Step 2: 与用户确认新公告内容；用户未说明是否发送到群聊 → type 取默认值 1
  └─ Step 3: popo_team_board_update(tid=1000114924, board="本周五下午 3 点开全员会议", type=1)
```
