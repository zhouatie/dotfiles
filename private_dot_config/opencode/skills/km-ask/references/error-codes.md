# 错误码

> 跨域错误码与调试流程，适用于所有 km-skills。

## 错误处理流程

```
发生错误
  │
  ▼
步骤 1: 是否为通用错误？（网络、认证、5xx）
  │      是 → 按通用错误码表处理
  │      否 → 步骤 2
  │
  ▼
步骤 2: 是否为产品级错误？（业务逻辑）
  │      是 → 查看对应产品域的错误码说明
  │      否 → 步骤 3
  │
  ▼
步骤 3: 是否为字段级错误？（参数格式）
  │      是 → 查看参考文档中的字段说明
  │      否 → 向用户报告未知错误
```

## 通用错误码（所有域）

| HTTP 状态码 | 错误码 | 描述 | 处理方式 |
|-------------|--------|------|----------|
| 400 | `BAD_REQUEST` | 请求格式错误 | 检查请求参数 |
| 401 | `UNAUTHORIZED` | 认证失败或过期 | 确认 popo-cli 登录状态是否正常（尝试重新登录） |
| 403 | `FORBIDDEN` | 权限不足 | 检查用户权限 |
| 404 | `NOT_FOUND` | 资源不存在 | 验证资源 ID |
| 409 | `CONFLICT` | 资源冲突（如重复） | 检查已有资源 |
| 422 | `VALIDATION_ERROR` | 请求体校验失败 | 检查字段格式 |
| 429 | `RATE_LIMITED` | 请求过于频繁 | 降低请求频率 |
| 500 | `INTERNAL_ERROR` | 服务器内部错误 | 向用户报告，建议稍后重试 |
| 502 | `BAD_GATEWAY` | 上游服务错误 | 向用户报告，建议稍后重试 |
| 503 | `SERVICE_UNAVAILABLE` | 服务不可用 | 向用户报告，建议稍后重试 |

## 产品级错误码

> 各技能可在自己的参考文档中定义域特定的错误码。以下为常见模式。

### 文档域

| 错误码 | 描述 | 建议操作 |
|--------|------|----------|
| `DOC_NOT_FOUND` | 文档不存在 | 验证文档 ID |
| `DOC_LOCKED` | 文档正被其他用户编辑 | 等待后重试，或联系编辑者 |
| `DOC_TOO_LARGE` | 文档超出大小限制 | 拆分为更小的文档 |
| `DOC_FORMAT_UNSUPPORTED` | 不支持的文档格式 | 检查支持的格式 |

### 搜索域

| 错误码 | 描述 | 建议操作 |
|--------|------|----------|
| `QUERY_TOO_LONG` | 搜索查询超出最大长度 | 缩短查询词 |
| `INDEX_NOT_READY` | 搜索索引正在重建 | 等待后重试 |

## 调试建议

1. 检查 `popo-cli` 返回的错误信息中的状态码和错误体
2. 对于认证错误，确认 popo-cli 登录状态是否正常（尝试重新登录）
3. 对于 5xx 错误持续出现，可能是 KM 服务暂时不可用
4. 向用户完整报告错误信息，不要静默忽略
