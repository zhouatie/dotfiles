# QA Testing & Verification Skill (质量保障与测试技能)

## 技能定位与使用时机
当你需要执行自动化回归测试、验证工程师提交的代码、编写测试用例或提报缺陷时使用此技能。

## 核心操作规程

### 1. 本地测试套件自动化运行
- 进入项目根目录执行已有测试：
  - Node/TS 项目：`npm test` 或 `npx jest --runInBand` 或 `npx vitest`
  - Playwright E2E 测试：`npx playwright test`
  - Python 项目：`pytest -v`
  - Rust 项目：`cargo test`
- 严禁在未实际执行测试的情况下伪造或凭空宣称测试全部通过。

### 2. 缺陷报告标准格式 (Bug Report)
当发现测试失败或回归缺陷时，必须使用以下格式规范提报：
```markdown
### 🐞 缺陷提报 · Bug Report
- **缺陷标题**：[模块名称] 缺陷简述
- **严重等级**：P0 (阻断) / P1 (严重) / P2 (一般) / P3 (轻微)
- **复现步骤**：
  1. 执行测试命令或访问具体 URL
  2. 观察断言结果
- **预期行为**：[描述预期正确表现]
- **实际行为**：[描述实际错误现象]
- **关键日志/堆栈**：
  ```
  [错误日志与堆栈信息]
  ```
- **修复建议**：[指出可能的原因与建议修复位置]
```

### 3. 质量门禁验收 (QA Sign-off)
当所有关键路径用例、边界条件全部 PASS，且无未解决的 P0/P1 阻塞时，发布门禁验收通过报告：
```markdown
### ✅ QA 验收通过报告 · Sign-off
- **测试范围**：[需求或功能模块]
- **执行结果**：共执行 N 项测试，PASS: X, FAIL: Y
- **自动化覆盖**：单元测试 / E2E 覆盖关键边界分支
- **黑盒核验状态**：核心操作路径核验完成
- **验收结论**：[准予合并/准予发布]
```
